## 저는 이러한 강점을 가지고 있습니다
1. 하나의 문제에 직면하면 끝까지 해결하고자 하는 집요함!
 * 매 프로젝트에서 완성도가 낮거나 구현도가 낮으면 해당 프로젝트의 작업에만 집중해서 어떻게든 완성시키고자 하였습니다.
2. 개발자적 사고를 갖고 새로운 내용을 빠르게 이해합니다.
 * 웹 프론트엔드와 Python에 대한 정보는 지식이 전무한 상태였으나 기존 개발자들의 코드 스타일과 함수 이름 특성을 빠르게 캐치해서 5일만에 웹 프론트엔드 정보를 습득하였습니다.
 * 이외에도 프로그래밍에만 집중하는 것이 아닌 해당 프로젝트의 도메인 지식을 얻고 이해하고서 의뢰에 맞게 개발하도록 합니다.
3. 최대한 다른 사람들의 의견을 수용합니다.
 * 프로젝트 결과가 안좋을 수 있는 의견은 이에 대한 반박과 이유, 그리고 설득을 합니다.
 * 저와 다른 의견이 나오더라도 그 의견을 존중합니다.

## 저는 이러한 기술을 잘 다룹니다.
1. Linux
   * 대다수의 서버 관련 프로젝트는 Azure Compute Machine을 사용해서 실제 웹, 서버로 운영을 해본 경험이 있습니다.
   * 개인 서버인 라즈베리 파이를 통해 Spring, DB를 배포하여 사용하고 WSL을 통해 Pytorch, Tensorflow, scikit 프로젝트를 진행했었습니다.
2. DB
   * 학과에서 주력으로 배웠던 과목입니다. 데이터베이스 설계와 구축, 운용까지 해보면서 데이터베이스 다루는 것에 흥미를 느꼈었습니다. 마침 게임 서버에서도 유저 DB와 아이템/콘텐츠 DB가 존재하기에 적용이 가능하다고 보고 있습니다.
3. Java
   * 초기부터 자바 중심으로 프로그래밍을 진행해왔으며 객체지향 프로그래밍 언어를 자바로 습득하면서 다른 객체지향 언어도 이해할 수 있습니다.
   * Spring Boot를 다루면서 MVC 모델 패턴을 학습할 수 있었으며 Android 앱 프로그래밍을 통해 API 참조도 잘 할 수 있게 되었습니다.
4. 웹 프로그래밍
   * KT에서 진행하는 에이블스쿨 8기에서 프론트엔드 내용인 HTML5, CSS, Javascript를 배웠으며 이를 활용하여 이전에 구현하지 못했던 프론트엔드 사이트를 만들 수 있게 되었습니다.
   * 별개로 DB를 활용한 Spring Boot 기반 프로젝트가 있습니다.
5. AWS
    * 최근 진행한 에이블스쿨 8기 교육과정에서 경험해볼 수 있었으며 실제 백엔드 서버 구현 및 배포에 사용해볼 수 있었습니다.
    * CodePipeline으로 CI를 구현하였으며 ArgoCD로 연결된 EKS 클러스터를 통해 배포를 진행하였습니다.

## 자기소개서
### 1. 지원한 직무와 관련된 본인의 역량(지식/Skill/경험 등)과 열정, 노력(프로젝트, 공모전, 대외활동, 논문 등)에 대해 기술해 주십시오.
> Backend Developer는 고객이 볼 수 없는 데이터 처리와 요청한 자료, 서버와 관련된 기능을 구현하는 개발자압니다. 서비스의 핵심 기능을 담당하는 것과 안정적인 운영 환경에 대한 책임감과 열정이 많아 해당 직무에 지원하게 되었습니다.
> 우선 대학교에서 데이터베이스 프로그래밍 과목을 통해 MariaDB를 접함과 동시에 Spring Boot를 배웠으며 조별과제로 간단한 릴레이 소설 사이트를 개발했었습니다. 다음 내용이 입력되고 난 뒤에 삽입된 내용을 주기적으로 봐야하기 때문에 입력 후 기존 페이지를 리다이렉트하는 방식으로 구현하였으며 팬텀 읽기를 웹 애플리케이션 단에서 방지할 수 있음을 알게 되었습니다. 이후 참여하게 된 에이블스쿨에서 앞선 경험을 바탕으로 웹 애플리케이션 백엔드 총괄로 작업했었습니다. 미니프로젝트에서는 AI 기반 도서관리 서비스의 백엔드 개발 중 데이터베이스 접근 관련 설정을 담당했으며 도서 수정 기능을 중점으로 개발하였습니다. 이때 DB의 일부기능을 JPA로 구현하여 사용했으며 개발 효율이 올라가는 장점이 있었습니다. 빅 프로젝트에서는 백엔드 초기설정을 담당, 검토하며 인프라 개발에 집중하였습니다. 팀원들이 작성한 코드를 보고 서로 의견을 나누었으며 API 정의서 기반으로 기능별로 개발을 지시하였습니다. MVC 패턴의 흐름에 맞춰서 개발하는 방식이 작성한 기능에 대한 일원화와 동시에 코드 흐름을 빠르게 파악할 수 있기 때문이었습니다. 그리하여 10일만에 핵심 기능을 구현할 수 있었으며 저는 해당 기간동안 AWS 내의 CI/CD, 운영환경을 구성할 수 있었습니다.

### 2. AI기술을 활용하여 해결한 문제나 수행한 프로젝트에 대해 구체적으로 기술하여 주십시오. (단, 문제해결 과정 또는 프로젝트 과정에서 AI기술을 활용(적용)한 구체적인 방법과 본인의 역할 및 기여도를 반드시 포함하여 작성)
> 미니프로젝트에서 스마트폰 행동 인식 분류를 진행했던 적이 있습니다. pandas를 통해 스마트폰 센서 데이터를 불러오고 heatmap을 기반으로 변수 중요도를 파악하였으며 이를 통해 5개의 변수가 행동 분석에 큰 영향이 있음을 확인하였습니다. 이를 기반으로 기계학습한 이후 딥러닝을 통해 행동 분석을 진행하였습니다. 딥러닝 모델 설계 과정에서 은닉층, 드롭아웃의 위치, 크기를 어떻게 설정하냐에 따라 정확도가 변할 수 있으며 복잡하게 설계한 모델이 항상 좋은 성능을 보여주지 못한다는 점을 알게 되었습니다. 
> 그리고 이때 했던 내용을 바탕으로 빅프로젝트에서 폭염 취약지역 분석에 참여하였었습니다. 당시 선정된 주제에서 X 변수로 지표면 온도와 식생지수, 취약인구수가 잡혀있는 상태에서 유동인구가 많은 지역에 폭염 저감시설이 주로 설치가 되어있다는 점을 얘기하였으며 이때 유동인구 파악 방법을 버스정류장 이용인구 수를 언급하였습니다. 이에 기계학습 데이터로 사용하기 위해 버스정류장ID를 기준으로 6월~8월의 평균 이용인구수를 도출하는 작업을 진행했습니다.. 이후 폭염 취약점수 도출을 위해 가우시안 혼합 모델(GMM)을 제시했으며 모델에 사용하기 위한 반영 비율을 기존 연구 논문에서 찾아 비율을 지정하였습니다. 답이 정해져있지 않은 점수를 도출해야하는 점에서 어려움을 느꼈지만 기준치를 계산한 값을 합산하여 도출한 값을 기준으로 점수를 계산하여 문제를 해결하였습니다.

### 3. KT의 핵심가치 중 본인에게 가장 중요한 가치를 선택하고, 그 이유와 이를 실현하기 위해 노력한 경험을 구체적으로 기술하여 주십시오. 
> 저에게 가장 중요한 가치는 협업이라 생각합니다. 이는 다른 가치인 고객, 기술, 오너십을 해결하는데 가장 중요한 기반으로 보고 있기 때문입니다.
> 학과에서 진행했던 조별과제, 팀 프로젝트에서 기술에 대해 어느정도 이해하고 있는 제가 직접 조장을 맡는 경우가 많았었는데 당시에는 원맨팀으로 밀어붙이는 경우가 많았습니다. 이때 프로젝트 결과는 총 8개의 프로젝트 중 3개만 만족스러운 프로젝트가 되었으며 이런 이유는 당시 제가 소통에 어려움이 있었다는 점이었습니다.
> 하지만 이번 에이블스쿨 프로젝트들을 진행하면서 협업의 중요성을 느끼게 되었습니다. 조장을 맡아 진행하거나 파트 총괄을 맡아 진행할 때 조원들의 의견을 들었으며 의견을 적극적으로 내세울 수 있게 물어보는 경우가 많았습니다. 대표적으로 빅 프로젝트에서 유의미한 주제와 온전히 구현된 결과물을 만들 수 있었던 이유는 사전 파트 분배에 대한 소통과 프로젝트 진행상황 공유, 막히는 주제가 있을 경우 서로 협업하는 과정을 통해 개발은 10일안에, 점수는 100점단위로 낼 수 있었습니다. 협업과정에서 고객 생각을 할 수 있으며 기술을 공유하고 협업의 책임감으로 오너십을 만들어 낸 것입니다. 앞으로 경험하게 될 모든 일들을 협업을 통해 해결해 나가고자 합니다. 감사합니다.
